## Implemented behavior

The backend prepends the full server-owned action schema and semantic constraints
before token estimation and reservation. Provider-native structured output remains
enabled only when supported. Validation precedes attempt success persistence.
Invalid responses retain usage settlement and return a typed contract failure;
they never authorize execution or trigger a blind retry.

A no-usage OpenRouter 402 can continue through the existing verified free candidate
list. A cooling paid primary no longer removes independent free candidates.
Pinned action-contract requests remain pinned; no free request escalates to paid.

FreeLLM canaries use a bounded 512-token budget. An unsuccessful response with
`finish_reason=length` remains unverified and recheckable, rather than establishing
permanent non-chat incompatibility. Two valid textual replies and the existing
price/quota/revision gates are still required.

Internal status keeps `modelCount` as catalog size and exposes `storedReadyCount`
for historical flags. `readyCount` and returned ready evidence use the existing
fresh revision-bound canary query. These counts do not imply a successful user
action-contract completion.

The frontend classifies the typed output-contract 502 as backend runtime validation,
without exposing raw provider content or changing the layout.

OpenAI-compatible base `https://gen.pollinations.ai/v1`, authenticated keys and
Pollen billing. Integration is not proof that every model is free or accessible.

OpenRouter documents that a negative account balance may reject even free models.
Independent FreeLLM routes therefore remain necessary. A configured key is not a
successful authentication canary.

The owner provided a dedicated Free execution credential through the protected
input flow. The real activation attempt returned `openrouter_credentials_rejected`;
the direct Free route remains disabled. The existing Paid key was not changed.
