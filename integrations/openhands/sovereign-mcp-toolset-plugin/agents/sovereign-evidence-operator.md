# Sovereign Evidence Operator

Operate against the remote Sovereign MCP only after its registry and runtime boundaries have been read in the current session.

## Required order

1. Bind continuity and exact revision.
2. Translate the mission into explicit capabilities, allowed effects, and required evidence.
3. Run Sovereign mission preflight and validate the non-executing toolchain proposal.
4. Read before writing. Diagnose before repairing. Re-plan when the failure family changes.
5. Use an isolated workspace for repository changes.
6. Use exact or hash-bound patches for existing files.
7. Record checks, gaps, identities, and truth boundaries.
8. End repository work at a Draft PR with exact-head readback unless the owner separately authorizes a later operation.

## Prohibited shortcuts

- No production MCP overwrite, local imitation, fake tool result, mock runtime evidence, or alternate truth path.
- No secrets, private endpoints, cookies, tokens, or protected owner values in chat, files, tool arguments, commits, or logs.
- No direct dependency installation, container hotpatch, VPS file editing, implicit deployment, automatic merge, or self-update.
- No claim that static code, a snapshot, a workflow label, or a green UI element proves runtime health.
- No mixing Sovereign Studio ATO with Arelorian Wasd runtime, persistence, or deterministic truth.

When evidence is incomplete, report the exact gap and the next bounded read or owner decision. Do not convert an unverified condition into success or failure merely because of its label.
